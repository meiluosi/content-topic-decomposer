# Output template

Use this structure, in the user's language. Trim sections that don't apply (for instance, if the user only asked for reuse of one experience, give section 5 and a short section 6). Keep the whole reply readable on a couple of screens.

```markdown
# Content map: <topic>

## 0. Assumptions
- Audience: …
- Goal: …
- Real material available: … (or: none stated; see "Material needed" column)
- Topic kind: …

## 1. Topic nodes
1. … 2. … 3. … (5–8 nodes: concepts, steps, decisions, mistakes, tools, results)

## 2. The map
For each type, a table. Stage: A stranger / B just learned / C about to act / D already using.

### Tutorial: clarity
| # | Working title | Angle (one line) | Stage | Format | Material needed |
|---|---|---|---|---|---|

### Case: credibility
(same columns; "Material needed" must say what real experience to dig up)

### Opinion: recognizability
(angle written as: common belief → my stance)

### Story: warmth
(angle written as the single scene)

### Resource: savability
(angle written as the artifact and who it's for)

## 3. Coverage check
| | A | B | C | D |
|---|---|---|---|---|
| Tutorial | #… | | | |
| Case | | | | |
| Opinion | | | | |
| Story | | | | |
| Resource | | | | |

Verdict (2–4 sentences): what's missing, what to make first, and why.

## 4. Hero material and reuse chains
For each of 2–3 hero experiences, use the same shape: the raw material needed (a fact sheet prompt), then a table of tutorial / case / story versions (+ opinion / resource if they fit) with protagonist, opening and ending, then the format fan-out. Do not give the first hero a full chain and the others a bullet list.

## 5. Suggested order
A short sequence, e.g.: open (opinion/story) → anchor (tutorial) → proof (case) → collect (resource). Add a calendar only if asked.

## 6. Next step
Offer: "I can draft any of these, or turn hero #1 into full versions once you send me the facts."
```

## Style notes
- Titles are working titles; make them concrete, not clever.
- In the "Material needed" column, name the kind of real experience to find; don't invent specifics.
- Don't repeat the same angle across types. If a tutorial and a case would say the same thing, change one.
- Prefer fewer, sharper ideas over padding to hit a count.
